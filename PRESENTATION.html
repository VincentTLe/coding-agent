§2 — Streaming + SSE

Why ChatGPT feels magical: time-to-first-token

Why stream at all?

BLOCKING
TTFT ≈ 10s
user stares at a blinking cursor
response arrives all at once
STREAMING
TTFT ≈ 200ms
text scrolls live, token by token
user starts reading immediately
SAME total time, FAR less perceived latency. Humans read at ~250 wpm; the model generates faster — so you start reading while it is still writing.

The 3 delta fields you must accumulate

1. delta.content — visible text. Just string-concat. (easy)
2. delta.reasoning_content — model's hidden thinking. Vendor extension. String-concat.
3. delta.tool_calls — TRICKY. One call across MANY deltas. JSON args dribble in. Parallel calls interleave by .index.
Arguments arrive CHUNKED: '{"pa' → 'th":"' → './foo' → '"}'. += per index, json.loads() at end.

The accumulator

if delta.tool_calls:
    for tcd in delta.tool_calls:
        idx = tcd.index
        if idx not in tool_calls:
            tool_calls[idx] = {"id": "", "name": "", "arguments": ""}
        if tcd.id: tool_calls[idx]["id"] += tcd.id
        if tcd.function:
            if tcd.function.name: tool_calls[idx]["name"] += tcd.function.name
            if tcd.function.arguments: tool_calls[idx]["arguments"] += tcd.function.arguments

§3 — Tool Calling

How an LLM "calls" Python functions

The problem

┌─────────────────────────────────────────┐ │ LLM = text-in / text-out function │ └─────────────────────────────────────────┘ ▼ We need a CONTRACT. → OpenAI tool calling protocol ┌─────────────────────────────────────────┐ │ But we want it to call Python: │ │ read_file('foo.py') │ └─────────────────────────────────────────┘
  • Server-side: JSON Schema declares tools.
  • Wire format: model emits tool_calls = [{id, name, arguments}].
  • Client executes, appends role:"tool", tool_call_id:..., content:result.

A tool schema in JSON

{
  "type": "function",
  "function": {
    "name": "read_file",
    "description": "Read the full contents of a text file.",
    "parameters": {
      "type": "object",
      "properties": {
        "path": {"type": "string", "description": "Relative path."}
      },
      "required": ["path"]
    }
  }
}
description is part of the prompt — the MODEL reads it. Write descriptions like prompts, not docstrings.

The 10 tools, by job

📝 FILE I/O
  • read_file — read contents
  • write_file — overwrite whole file
  • apply_patch — surgical search/replace
  • multi_edit — atomic batched edits
🔍 DISCOVERY
  • list_dir — directory listing
  • glob_files — match a glob pattern
  • grep_files — regex search across files
⚙️ EXECUTION
  • run_bash — shell command
  • run_python — eval a Python snippet
🤖 DELEGATION
  • spawn_subagent — subprocess child agent
  • timeout 300s · max_iters=8
apply_patch: old_text must match exactly once — 0 hits → read again; >1 hit → ambiguous, widen context. Token-efficient vs rewriting the whole file. multi_edit applies many such edits atomically.
Four jobs, ten tools. FILE I/O: read/write are the blunt instruments; apply_patch and multi_edit are the precision ones — apply_patch sends only the bytes that change, so it's far cheaper in tokens than re-emitting a 300-line file, and the exactly-once rule is a safety property (no blind replace-all). DISCOVERY replaces fragile run_bash one-liners with structured list/glob/grep. EXECUTION is run_bash plus run_python for quick eval. DELEGATION is spawn_subagent — it launches a fresh agent in a child subprocess, so the subtask gets its own clean context window and can't pollute the parent's history; the 300s timeout is hardcoded and max_iters defaults to 8. All ten live in one registry (src/tools.py) — adding a tool needs no changes to the ReAct loop.

The dispatcher

src/tools.py:217
def execute_tool(name: str, arguments_json: str) -> str:
    if name not in TOOLS:
        return f"ERROR: unknown tool {name}. Available: {list(TOOLS)}"
    try:
        args = json.loads(arguments_json) if arguments_json else {}
    except json.JSONDecodeError as e:
        return f"ERROR: bad JSON arguments: {e}"
    try:
        result = TOOLS[name](**args)
    except Exception as e:
        return f"ERROR: {name} crashed: {e}"
    return result
Every failure becomes an ERROR STRING the model can read. Never raise — let the model self-correct on the next turn.

Both reasoning AND acting alone fail at multi-step tasks. ReAct's insight: alternate them.

Thought → Action → Observation

=== Turn 1 === [assistant] I'll list the repo to see what's there. [tool] run_bash({"command": "ls"}) [tool result] algorithms.py calculator.py test_*.py
=== Turn 2 === [assistant] Running tests to see failures. [tool] run_bash({"command": "pytest -x"}) [tool result] FAILED test_calculator::test_add - assert -1 == 5
=== Turn 3 === [assistant] add() uses - instead of +. Fixing. [tool] apply_patch({"path": "calculator.py", "old_text": "return a - b", "new_text": "return a + b"}) [tool result] patched calculator.py: replaced 13 chars
=== Turn 4 === [assistant] Re-running. [tool] run_bash({"command": "pytest"}) [tool result] 11 passed
=== Turn 5 === [assistant] All tests pass. Done. Agent finished. (no more tool_calls)

Termination = no tool_calls

Modern ReAct termination = assistant returns content WITH no tool_calls

No magic Finish[answer] sentinel. The model just stops asking for tools.

The whole loop in 12 lines

for i in range(1, max_iters + 1):
    resp = client.chat.completions.create(
        model=MODEL, messages=messages,
        tools=TOOL_SCHEMAS, tool_choice="auto",
    )
    msg = resp.choices[0].message
    messages.append(msg.model_dump(exclude_none=True))

        return  # TERMINATE

            "role": "tool",
            "tool_call_id": tc.id,
            "content": result,
        })

The threat model

"The LLM emits arbitrary paths.
We cannot trust the prompt."
💀
Prompt injection

The Python CODE must refuse. Not the prompt. A policy is a suggestion; a mechanism is enforced.

The 4-line sandbox

WORKSPACE = Path.cwd()  # set once at startup via set_workspace()

def _safe_path(path: str) -> Path:
    p = (WORKSPACE / path).resolve()  # absolutify + symlinks + collapse ..
    if WORKSPACE not in p.parents and p != WORKSPACE:
        raise ValueError(f"path {p} escapes workspace {WORKSPACE}")
    return p
Trick 1 — .resolve() follows symlinks AND collapses .. → the REAL target path.
Trick 2 — .parents verifies target is descendant of WORKSPACE.
src/tools.py:51-67. 17 lines = the entire security boundary.

Worked example: ../../etc/passwd

# Model emits: read_file("../../etc/passwd")

p = (WORKSPACE / "../../etc/passwd").resolve()
#   = /home/tle/.../demo_repo/../../etc/passwd
#   = /etc/passwd                        # ← collapsed

list(p.parents) == [Path("/etc"), Path("/")]
WORKSPACE in p.parents == False          # not in list
p == WORKSPACE        == False

→ raise ValueError("path /etc/passwd escapes workspace ...")
→ caught by execute_tool
→ returns "ERROR: path /etc/passwd escapes workspace ..."
→ model sees error, retries with valid path or gives up
This does NOT protect against run_bash("cat /etc/passwd"). Shell sandbox is weaker. Production agents need Docker / seccomp.

§9.5 — Context Compaction

The conversation outgrows the context window. Now what?

The problem: the list never stops growing

messages[] IS the memory — so every turn it gets longer. Tool results (pytest output, file dumps) are huge.
The wall: our context window is 32K tokens (--max-model-len 32768). Overflow it and vLLM rejects the request — the agent simply dies mid-task.
flowchart LR

~2K tok"] --> B["turn 8
~15K tok"] --> C["turn 15
~26K tok"] --> D["💥 32K
REJECTED"]
  style D fill:#2b1a1a,stroke:#ff7b7b,color:#ff7b7b

Long autonomous tasks (the whole point of an agent) hit this fast. We need to shrink history without losing the thread.

The solution: summarize old, keep recent

When the token estimate crosses COMPACT_THRESHOLD_TOKENS = 24000 (~75% of context — leaving headroom)...
  1. Keep the system message (agent persona) verbatim.
  2. Summarize everything in the middle into one synthetic system message — an LLM call that preserves tool calls, file paths, decisions, and errors.
  3. Keep the most recent KEEP_RECENT_MESSAGES = 10 messages verbatim — the model needs immediate context.
Before:  [system, m1, m2, m3, ..., m25]        26 messages
After:   [system, summary, m16, ..., m25]       12 messages
          ↑       ↑        ↑
          kept    LLM-gen  last 10 verbatim
This mirrors what Claude Code's auto-compact and ChatGPT's memory do under the hood. The estimator is cheap — roughly chars/4 plus a flat overhead per message, no real tokenizer needed. Threshold is 24K not 32K so there's room for the summary call itself and the next response. The summary call runs with thinking OFF (it's deterministic, don't burn reasoning tokens) and caps at 600 tokens, and the prompt explicitly asks to preserve tool calls, file paths, decisions, and errors — those are exactly what the model needs to resume the task. KEEP_RECENT=10 keeps the live working set intact.

The subtlety: don't orphan a tool result

API rule: every role:"tool" message MUST be preceded by an assistant message whose tool_calls[i].id matches its tool_call_id. Break that pair → 400.
A naive "keep the last 10" can slice between an assistant(tool_calls) and its tool result — leaving an orphan tool message the API rejects.
# Start at -keep_recent, then WALK FORWARD to the next user message.
# user messages are clean turn boundaries (no tool dependency).
split = len(messages) - keep_recent
while split < len(messages) and messages[split].get("role") != "user":
    split += 1
if split >= len(messages):
    return messages, "skipped (no clean user boundary)"  # bail, don't corrupt
examples/06_chat.py:139-191 — split on a user-role message so every tool_call/tool_result pair stays together.
This is the single non-obvious bug in compaction and the reason a from-scratch implementation is worth showing. tool_call_id pairing is the same invariant from the very first roles slide — it bites you again here. The fix: never cut mid-turn. We start at -10, then walk forward until we land on a user message, which is always a clean boundary because the user never depends on a prior tool_call. If we walk off the end (rare — e.g. trailing tool messages), we bail and skip compaction entirely rather than send a malformed history. Better to risk overflow than guarantee a 400.

Driving it: /compact and /tokens

Automatic
Before each turn, estimate tokens. If over 24K → compact, then continue. The agent self-heals without user action.
Manual
/tokens — show current estimate vs threshold (green / yellow / red).
/compact — summarize now, even below threshold.
you> /tokens ~21340 tokens used [threshold: 24000] (yellow — getting close) ... a few turns later, automatically ... [context ~24600 > 24000, summarizing history...] compacted: 26 → 12 messages
Same building blocks as the rest of the agent — a slash-command dispatcher and a token budget. No framework, ~50 lines.
Two ways to trigger. Automatic is the real path: every turn, before calling the model, estimate the budget and compact if over threshold — so a long task never crashes. Manual gives control during a demo: /tokens is a read-only gauge color-coded green/yellow/red against the 24K threshold, and /compact forces summarization immediately even if you're under budget — handy to show the mechanism on stage without waiting for a 26-message history. The whole thing is just a slash-command dispatcher plus the estimator; no LangChain, no memory framework.
