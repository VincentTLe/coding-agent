01Hooks · Skills · Subagents — ba khái niệm

Ba cơ chế mở rộng của Claude Code, khác nhau ở ai kích hoạt và khi nào. Hiểu trục này là hiểu hết.

Skill

Một file SKILL.md = một quy trình viết sẵn dưới dạng văn bản hướng dẫn. Khi được gọi, nội dung file được nạp vào ngữ cảnh và Claude làm theo các bước đó.

Ai kích hoạt: bạn (gõ /tên-skill). Hai skill ở đây đặt disable-model-invocation: true nên chỉ bạn gọi được, Claude không tự ý chạy.

Subagent

Một "nhân viên phụ" có system prompt riêng và bộ tool giới hạn riêng, chạy trong ngữ cảnh tách biệt. Định nghĩa bằng 1 file .md trong .claude/agents/.

Ai kích hoạt: Claude chính ủy thác sang, hoặc bạn yêu cầu. Của ta chỉ có tool read-only (Read/Grep/Glob) → không thể sửa gì, chỉ soi & báo cáo.

Hook

Một lệnh shell mà harness Claude Code (không phải model) tự chạy tại một thời điểm trong vòng đời — ví dụ PostToolUse = ngay sau khi một tool chạy xong. Khai báo trong settings.json.

Ai kích hoạt: hệ thống, tự động, theo sự kiện. Không phụ thuộc việc model "nhớ" hay không — đó là sức mạnh của hook.

Trục phân biệt: ai bấm nút?

Bạn gõ /demoSKILL → Claude đọc & làm theo
·
Claude ủy thácSUBAGENT chạy ngữ cảnh riêng

Mấu chốt Skill & subagent là chỉ dẫn cho model (model vẫn quyết định hành động). Hook là code chạy thật do harness thực thi — nên nó là chỗ duy nhất bạn ép được "luôn luôn làm X", không lệ thuộc vào việc model có nhớ hay không.

03Skill /start-vllm — bật model server

Agent không chạy được nếu không có model server. Skill này bật vLLM đúng y các flag trong scripts/start_vllm.sh, đợi nó sẵn sàng, rồi xác minh endpoint sống.

Nó làm gì, theo thứ tự

curl port 8765đã chạy chưa?
→
bash scripts/start_vllm.shQwen3-14B trên GPU1
→
đợi log"Application startup complete"
→
curl lạiverify model có mặt

Các flag không bịa — skill chạy thẳng script có sẵn, vốn đã set: VLLM_USE_FLASHINFER_SAMPLER=0 (dùng sampler PyTorch-native vì server này không có nvcc), CUDA_VISIBLE_DEVICES=1 (ghim GPU1, để GPU0 cho người khác), --max-model-len 32768, --gpu-memory-utilization 0.75, --reasoning-parser qwen3, --tool-call-parser hermes, --port 8765.

Vì sao đợi log thay vì đoán Nạp Qwen3-14B (BF16, ~28 GB) mất 1–3 phút. Skill poll /tmp/vllm.log tới khi thấy dòng Application startup complete rồi mới verify — không "ngủ 60 giây rồi hy vọng".
Chống chạy 2 lần Bước 1 kiểm tra trước: nếu port 8765 đã trả Qwen/Qwen3-14B, skill dừng ngay — GPU1 chỉ đủ chỗ một bản (ở mức 0.75 VRAM), khởi động lần hai sẽ CUDA out of memory.

04Skill /demo — chạy màn demo chuẩn

Kịch bản tham chiếu của dự án: agent nhận một demo_repo/ đang lỗi, rồi lặp pytest → read_file → apply_patch → pytest tới khi 11/11 test pass — chỉ sửa source, không bao giờ sửa test.

Bốn bước, có pre-check và reset

curl 8765vLLM up? nếu không → /start-vllm
→
git checkout -- demo_repo/trả về trạng thái buggy
→
cli/solve.py "Fix all failing tests…"ReAct trace verbose
→
pytest demo_repo/verify 11 passed

Lệnh chạy agent là entrypoint thật đã verify — cli/solve.py là wrapper argparse mỏng quanh run_agent(), workspace mặc định là demo_repo/, --max-iters mặc định 15:

.venv/bin/python cli/solve.py "Fix all failing tests in demo_repo/"
Vì sao reset trước Demo chỉ "diễn" được nếu demo_repo/ bắt đầu ở trạng thái lỗi (2 bug trong algorithms.py: is_prime và factorial đều dùng range(1, n) → 5/11 test fail). Nếu lần chạy trước đã sửa rồi, agent không có gì để làm. git checkout -- demo_repo/ trả lại bản buggy. Không dùng git clean (sẽ xóa stray fibonacci.py — vô hại nhưng không cần đụng).
Pre-check vLLM Nếu curl port 8765 fail, skill dừng và nhắc bạn chạy /start-vllm trước — tránh chạy demo vào endpoint chết rồi nhận một đống lỗi khó đọc giữa buổi present.

05Subagent sandbox-guardian — canh gác tools.py

Một reviewer chỉ-đọc (tool: Read · Grep · Glob). Mỗi khi src/tools.py thay đổi, nó kiểm tra 3 bất biến an toàn mà AGENTS.md tuyên bố là "load-bearing, không thể nhân nhượng".

① Mọi tool đụng file đi qua _safe_path

7 tool chạm filesystem (read_file, write_file, apply_patch, multi_edit, grep_files, glob_files, list_dir) phải resolve path qua _safe_path(path, workspace) trước khi mở file. Đây là phòng thủ CWE-22 path-traversal.

Flag nếu ai đó nối path bằng tay rồi mở thẳng, hoặc làm yếu chính _safe_path.

② Tool RETURN "ERROR: …", không raise

Mọi nhánh lỗi phải return chuỗi bắt đầu "ERROR: " để model đọc và tự sửa — vòng lặp ReAct không được chết vì một tool fail. execute_tool() là lưới an toàn cuối: try/except biến exception thành chuỗi error.

Flag nếu có raise không được bắt, hoặc ai đó thu hẹp try/except trong dispatcher.

③ workspace là keyword-only, không global

Mọi hàm tool có chữ ký (…, *, workspace: Path); execute_tool() tự inject. Không có global WORKSPACE, không có set_workspace(). Nhờ vậy nhiều agent (vd subagent) chạy khác workspace trong cùng process vẫn an toàn.

Flag nếu global quay lại, hoặc workspace bị chuyển thành positional/default.

Vì sao là subagent read-only, không phải hook Ba bất biến này cần đọc hiểu code (ngữ nghĩa), không phải so khớp văn bản máy móc — đó là việc của model. Cho nó tool read-only nghĩa là dù phán đoán sai, nó cũng không thể tự sửa code; nó chỉ báo cáo PASS/FAIL kèm số dòng để bạn quyết định. An toàn tuyệt đối.

Cách dùng: sau khi sửa src/tools.py, nhờ Claude "review tools.py bằng sandbox-guardian", hoặc Claude tự ủy thác khi thấy file đó đổi.

06Hook — tự chạy test sau khi sửa code

Cơ chế tự động duy nhất ở đây. Sau mỗi lần Claude dùng Edit hoặc Write đụng vào file trong src/ hoặc tests/, harness tự chạy pytest tests/ và in kết quả. Không chặn, không hỏi, luôn an toàn.

Đúng schema chính thức của Claude Code

Cấu trúc: hooks → PostToolUse → mảng các nhóm {matcher, hooks:[{type, command}]}. matcher lọc theo tên tool, hỗ trợ danh sách ngăn bằng |. Đây là settings.json đầy đủ:

{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "timeout": 120,
            "statusMessage": "Running unit tests (tests/)…",
            "command": "f=$(jq -r '.tool_input.file_path // empty'); case \"$f\" in */src/*|*/tests/*) cd \"$CLAUDE_PROJECT_DIR\" && out=$(timeout 120 .venv/bin/python -m pytest tests/ -q -x 2>&1); echo \"[sandbox-tests] after editing $f:\"; echo \"$out\" | tail -n 5 ;; *) : ;; esac; exit 0"
          }
        ]
      }
    ]
  }
}

Đọc lệnh shell từng mảnh

jq đọc stdinlấy tool_input.file_path
→
case lọccó chứa /src/ hay /tests/?
→
pytest tests/ -q -xtrong $CLAUDE_PROJECT_DIR
→
echo 5 dòng cuốirồi exit 0
  • Vì sao lọc /src/ & /tests/: Edit/Write có thể đụng bất kỳ file nào (kể cả file HTML này). Ta chỉ chạy test khi sửa code logic — sửa README hay HTML thì hook im lặng (: ;; = no-op).
  • Vì sao -q -x: -q gọn, -x dừng ở fail đầu tiên. Bộ 21 test chạy ~0.3–0.6s nên gần như tức thì.
  • Vì sao timeout 120 + field "timeout": 120: hai lớp bảo hiểm để hook không bao giờ treo phiên làm việc.
  • Vì sao luôn exit 0: PostToolUse chạy sau khi tool đã xong nên về bản chất không thể "rollback" — và ta cố tình exit 0 để nó tuyệt đối không nổi lên như lỗi làm gián đoạn. Test fail vẫn hiện ra (bạn thấy dòng FAILED), chỉ là không chặn.
  • $CLAUDE_PROJECT_DIR: biến môi trường Claude Code cấp = gốc repo, nên .venv/bin/python trỏ đúng venv (Python 3.12.3).
Đã test thủ công 5 ca Sửa src/tools.py → chạy pytest (21 passed). Sửa tests/… → chạy. Sửa README.md → im lặng. Thiếu file_path → im lặng, không crash. Test fail giả lập → hiện FAILED rõ ràng nhưng vẫn exit 0. Mọi ca đều trả về exit code 0.
CỐ TÌNH không có PreToolUse chặn cứng Một hook PreToolUse chặn-cứng (vd cấm sửa file nào đó) quá rủi ro ngay trước buổi present — lỡ cấu hình sai là kẹt cả workflow. Ở đây chỉ có một hook PostToolUse quan sát-và-báo. Việc thực thi bất biến sandbox để cho subagent read-only lo (mục 05), không để hook chặn.

08An toàn trước buổi present (Fri 2026-05-29)

Mọi lựa chọn ở đây nghiêng về thấp rủi ro, vì sắp tới ngày present và không được phép làm hỏng workflow.

Không đụng src/

Bốn automation chỉ là lớp bao quanh; không sửa một dòng nào trong mã agent. Gỡ bỏ = xóa .claude/ là xong, repo trở lại y nguyên.

Hook không chặn, luôn exit 0

Trường hợp xấu nhất hook gặp lỗi cũng chỉ in vài dòng thừa rồi thoát sạch — không bao giờ chặn Edit/Write hay treo phiên.

Skills chỉ bạn gọi được

Cả hai đặt disable-model-invocation: true → Claude không tự ý bật server hay chạy demo giữa chừng. Bạn nắm nút bấm.

Subagent read-only

Chỉ Read/Grep/Glob → dù phán đoán sai cũng không sửa được gì. Chỉ báo cáo.

Không PreToolUse chặn cứng

Cố tình bỏ qua loại hook rủi ro nhất. Không có "rào chắn" nào có thể vô tình khóa thao tác của bạn.
